# GoWAF v1.6.0 与雷池（SafeLine）社区版对比

> 对比基线：GoWAF `v1.6.0`（commit 21a32e5，2026-11-18 正式发布）；雷池社区版 `v9.4.4`（2026-11-11，上一轮对比时为 v9.2.7）。
> 雷池数据来源：GitHub Releases（v9.2.7→v9.4.4 全量 changelog）、README、官方版本对比页。标注「厂商口径」的指标为雷池自published，未独立复现。
> 本文只做技术判断，不含商务建议。

---

## 一、结论摘要（相对 v1.5.0 对比的六大变化）

1. **检测理念代差已收窄为「广度差」**：v1.6.0 新增语义检测通道（第四引擎），从 SQLi/XSS 两类扩到 **9 类**（+命令注入/RCE/XXE/SSRF/SSTI/表达式注入/反序列化），结构级判定而非关键词；雷池仍是 40+ 类。**「有无语义引擎」的差距已消除，剩下的是类型覆盖面与样本规模验证。**
2. **性能天花板被打破**：CRS 调度闸门上线后，全引擎吞吐实测 **3,998 → 12,836 RPS（3.2 倍）**，p99 13.5ms，干净流量 100% 旁路、攻击样本零漏拦。之前「CRS 占 75% 开销」是 GoWAF 最大短板，现已解决。
3. **接入形态护城河补齐**：`server.detect_listen` 提供 `POST /detect`（完整 JSON 协议）+ `GET /check`（nginx auth_request / Traefik forwardAuth 式）双端点，配 nginx lua-resty 与 Traefik 集成示例——**GoWAF 也能当「独立检测引擎」被外部网关调用了**，对标雷池 T1K。
4. **人机验证强度升级**：PoW 之上加浏览器环境信号校验（webdriver/核数/屏幕/时区/WebGL/耗时结构）+ 最小耗时校验，headless 自动化要么 webdriver=true 要么缺字段，真实浏览器无感——追平雷池「无感放行」的思路。
5. **雷池 v9.2.7→v9.4.4 对 CE 没有质变**：新增多是 Lite/Pro 功能（ASN 算子、上游动态解析、Beta 通道），CE 侧仅有 Deny 规则 Monitor 模式、自定义健康检查路径、威胁情报共享升级与大量加固/修复。**CE 的硬限制（10 站点、单线程、无告警外发、日志不可导出）原封未动。**
6. **新一轮差距集中在 P1**：语义类型广度与样本库规模验证、JA4/TLS 指纹、请求防重放、等候室、Syslog 日志外发、自定义拦截页、控制台 TOTP——多为「小而确定」的工程项，路径清晰。

## 二、技术栈与架构

| 维度 | GoWAF v1.6.0 | 雷池 CE v9.4.4 | 评价 |
|---|---|---|---|
| 语言/运行时 | Go 1.27，单静态二进制（`CGO_ENABLED=0`） | 管理面 Go + gRPC；数据面 Tengine(Nginx) + Lua；检测器独立服务（镜像分发） | GoWAF 交付更简单；雷池复用 Nginx 生态 |
| 数据面 | `net/http` + `httputil.ReverseProxy`，HTTP/2，WebSocket 原生升级 | Tengine（Nginx 分支），host 网络 | 雷池的 Nginx 底座在连接管理/TLS 细节更成熟（v9.3.7 起 backlog=65536 + reuseport） |
| 进程模型 | 单进程多核扩展 + 引擎级 panic 隔离 + 超时熔断 | 7 容器（postgres/mgt/detect/tengine/…），进程级隔离 | 雷池故障域更小；GoWAF 运维面为零 |
| 存储 | SQLite（WAL），零外部依赖 | PostgreSQL 15 | 单机 SQLite 足够；多节点必须 PG |
| 前端 | Vue 3.5 + Naive UI + ECharts，`go:embed` 内嵌 | 未开源（独立前端包） | — |
| 部署形态 | 单二进制 / 宝塔、1Panel、小皮 / 原生 Apache/Nginx/IIS / Windows 服务 / Docker | 仅 Docker Compose，要求宿主机让出 80/443 | **GoWAF 明显占优** |
| **检测接入方式** | ✅ **新增**：独立检测端口 `/detect` + `/check`，token 鉴权，nginx lua / Traefik forwardAuth 示例 | ✅ T1K 协议（TCP 8000），ingress-nginx / Kong / Traefik / OpenResty 插件成套 | **差距已基本抹平**；雷池胜在插件成套与生态文档 |
| 最低资源 | 单核即可跑 | 1C1G/5GB | 相当 |
| 许可 | AGPL-3.0 | GPL-3.0（个人版许可限制商用） | 定位差异 |
| 开源完整性 | 全栈源码（控制台/规则/脚本） | 管理面开源；**核心检测引擎与 Tengine 镜像二进制分发** | 「读代码学引擎」只有 GoWAF 能做 |
| 社区体量 | 自有仓库（小） | ~24k stars / 1.6k forks | 雷池生态与文档成熟度高一个量级 |

## 三、检测能力

| 能力 | GoWAF v1.6.0 | 雷池 CE v9.4.4 | 说明 |
|---|---|---|---|
| 检测范式 | **四引擎**：自研 YAML 规则（AC 预筛 + RE2）+ OWASP CRS v4.30（含调度闸门）+ libinjection（SQLi/XSS 词法指纹）+ **语义通道** | 自研语义分析引擎（宣称不依赖规则、防 0day）+ 规则兜底 | **理念差距已消除**；雷池覆盖更广、有样本级验证 |
| 语义覆盖类型 | **9 类**：SQLi、XSS（libinjection）+ cmdi/rce/xxe/ssrf/ssti/expr（JNDI·SpEL·OGNL）/deser（语义通道，结构级判定，Header 额外扫 JNDI） | 宣称 40+ 类（SQLi/XSS/代码注入/CRLF/LDAP/XPath/爆破/后门…） | **主要剩余差距**：类型广度 + 大样本验证 |
| 语义判定方式 | 「结构」而非关键词：元字符紧邻系统命令、DOCTYPE+ENTITY 成对、危险 scheme、模板运算链、序列化魔数；单类 35~50 分压在 block 阈值下 | 黑盒，不可考 | GoWAF 语义通道可读可调（例外规则 `sem-*`） |
| 检测前解码 | base64（≤3 层）、gzip/deflate/zlib、JSON/JS `\uXXXX` 多层解码（v1.5.0 起） | 深度解码 + 语义还原 | 相当 |
| **CRS 性能治理** | ✅ **新增**：AC 可疑度预筛（默认关，开启实测 3.2 倍）、静态资源旁路（默认开）、二进制 body 跳过 phase-2（默认开）、路径豁免、编译期号段移除；旁路按原因打点 | Nginx 底座自带静态处理；无等价「规则引擎预筛」概念 | **GoWAF 独有**，CRS 类产品的通用痛点 |
| 引擎加固 | 超时熔断、panic 隔离、`fail_mode` open/closed | 独立检测服务，进程级隔离 | GoWAF 同进程内隔离 |
| 效果数据 | 40+ 手工攻击样本（含变形）全检出、benign 零误报；**缺大样本基准** | 33669 样本：检出 71.65% / 误报 0.07%（厂商口径） | GoWAF 需要建样本库跑分 |
| 自定义规则 | 访问策略条件树 + 例外规则 + YAML 热载 | 自定义规则 + 社区在线规则订阅；v9.4.4 起 Lite/Pro 支持 ASN 匹配 | 雷池有订阅生态；ASN 算子 CE 没有 |
| 规则灰度 | ✅ Deny 类操作可先 observe 后 block（引擎模式） | v9.4.4 CE 新增 Deny 规则 **Monitor 模式**（只记日志不拦截） | 同类能力各自补齐 |
| 威胁情报 | 10 预设源 + 自定义 Header/Token + JSON 列表 | 社区共享情报（内置） | GoWAF 更开放 |
| TLS/JA4 指纹 | ❌ | ✅ JA4 + 恶意指纹拦截（8.10.0 起） | **P1 可低成本跟进**（算法公开） |
| 人机验证 | ✅ **升级**：PoW + 浏览器环境信号结构校验（webdriver/核数/屏幕/时区/WebGL）+ PoW 最小耗时校验；Cookie 免检 | 环境检测（调试行为/键鼠轨迹）+ 验证码 | 思路追平；雷池多验证码与行为轨迹 |
| 请求防重放 | ❌ | ✅ | P1 小项 |

## 五、性能

### 5.1 本机实测（GoWAF，Windows 6 核 / 回环 / 1.6KB HTML / keep-alive / 无 TLS）

| 场景 | 吞吐 | p50 | p90 | p99 |
|---|---|---|---|---|
| 裸后端，C=64 | 62,969 RPS | 0.88ms | 1.65ms | 3.29ms |
| 全引擎（v1.5.0 基线，CRS 无治理） | 3,998 RPS | — | — | — |
| 全引擎（v1.5.0，关 CRS） | 17,134 RPS | 3.34ms | 6.07ms | 9.19ms |
| **全引擎 + CRS 预筛（v1.6.0）**，C=64 | **12,836 RPS（3.2 倍）** | 4.4ms | — | 13.5ms |
| 全引擎，C=1（单请求时延） | 916 RPS | **1.04ms** | 1.25ms | 1.86ms |

> 回归验证：预筛开启时 SQLi/命令注入/JNDI/SSTI/SSRF/XSS 样本全部 403；`waf_crs_skipped_total{reason="prescreen"}` 显示干净流量 100% 旁路。

| 指标 | GoWAF v1.6.0 | 雷池 CE v9.4.4 | 说明 |

## 六、优缺点对照

### GoWAF v1.6.0

| 优势 | 劣势 |
|---|---|
| 单二进制交付，宝塔/1Panel/IIS/Windows 全覆盖，落地摩擦极低 | 语义类型覆盖 9 类 vs 40+ 类，且缺大样本跑分 |
| 四引擎 + CRS 调度闸门：12.8k RPS、干净流量 100% 旁路 | 无 JA4 指纹、防重放、等候室、Syslog 外发 |
| 检测 API 双端点 + 集成示例，可作独立引擎被网关调用 | 无 SSO/多用户/2FA/报表，企业采购会卡 |
| 人机验证双层（PoW + 环境信号），headless 暴露点明确 | 自定义拦截页缺位 |
| 防篡改、脱敏、多上游、地域封禁、告警外发、MCP 可写——CE 多为付费项 | 社区体量与文档成熟度远不及雷池 |
| Prometheus 指标 + 全栈开源，规则可读可调 | 单进程，故障域大于容器化方案 |

### 雷池 CE v9.4.4

| 优势 | 劣势 |
|---|---|
| 语义引擎 40+ 类，厂商口径检出 71.65%/误报 0.07% | 个人版裁剪狠：10 站点、单线程 800 QPS、无告警外发、日志不可导出 |
| 产品化成熟：SSO、TOTP、验证码、行为轨迹、等候室、防重放 | 部署重：Docker + PG + 7 容器，必须让出 80/443 |
| 生态：成套网关插件、社区规则订阅、24k stars | 核心引擎闭源，学不到检测算法 |
| v9.4.x 持续加固（面板/引擎边界、容器权限、CVE 响应快） | 多上游/地域封禁/ASN/自定义拦截页/动态解析均锁付费版 |
| 文档、多语言、合规口径完整 | 国内面板（宝塔/小皮/IIS）零适配 |

## 八、一句话定位（v1.6.0 版）

> v1.5.0 时的判断是「检测理念有代差」；v1.6.0 之后代差已收窄为**广度差与样本验证**，且在性能治理（12.8k RPS）、检测接入形态（detect API）、人机验证强度三个短板上完成补课。
> 现在的格局：**GoWAF = 功能最全、落地最快、可读可调的单机开源 WAF；雷池 = 检测最准、生态最完整的 Docker 型 WAF。** 下一阶段的胜负手是 P1-1（语义广度 + 样本库跑分）——做出公开可复现的检出/误报数据，就能把「我们不差」变成「我们不输」。
