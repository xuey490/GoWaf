# P1 新特性使用指南（v1.6.1）

本文覆盖 v1.6.1 新增的 7 项 P1 特性（对应《v1.6.0-与雷池社区版对比》新 P1 清单第 2~8 项）。
所有开关均为设置键（控制台「系统设置」或 `PUT /api/settings/{key}`），保存后经 Reload 热生效，无需重启。

---

## 1. JA4/TLS 指纹识别与恶意指纹拦截（P1-2）

**原理**：包装 TLS Listener 在握手阶段解析 ClientHello，按 FoxIO JA4 规范计算指纹
（`t13d1516h2_8a1b2c3d4e5f_a1b2c3d4e5f6` 三段式），HTTP/1.1 与 HTTP/2 均适用。
指纹按连接四元组登记，请求处理时按 `RemoteAddr` 查表，连接关闭即清理。

| 设置键 | 默认 | 说明 |
|---|---|---|
| `guard.ja4.enabled` | `true` | 采集指纹并写入事件库（`events.ja4` 列），关闭后不采集也不拦截 |
| `guard.ja4.blocklist` | 空 | 恶意指纹黑名单，逗号分隔，命中即 403 拦截 |
| `guard.ja4.block_builtin` | `false` | 是否拦截内置清单指纹（见下方诚实声明） |

- 事件列表 API 返回值新增 `ja4` 字段，可在拦截详情中看到攻击者客户端指纹。
- 明文 HTTP 站点无 TLS 握手，指纹为空，属预期行为。

**诚实声明**：内置清单（`internal/ja4/malicious_ja4.json`）目前仅收录两条本机真实采集种子
（Go 标准库客户端、Windows curl/Schannel），**并非完整恶意指纹库**。脚本栈指纹亦被正常
工具使用，故 `block_builtin` 默认关闭。拦截效果主要依赖管理员根据事件库积累配置
`guard.ja4.blocklist`；欢迎社区贡献经真实采集验证的指纹条目。

## 2. Syslog(RFC5424)/Kafka 日志外发（P1-3）

拦截事件异步推送至 SIEM。有界队列（默认 4096）+ 单 worker，队列满丢弃并计数
（fail-open，不影响业务），丢弃数见指标 `waf_logship_dropped_total`，
成功条数见 `waf_logship_sent_total`。

| 设置键 | 默认 | 说明 |
|---|---|---|
| `logship.enabled` | `false` | 总开关 |
| `logship.min_action` | `block` | 外发门槛：`all` 全部 / `log` 记录级以上 / `block` 仅拦截 |
| `logship.syslog.enabled` | `false` | Syslog 渠道开关 |
| `logship.syslog.addr` | 空 | 目标 `host:port` |
| `logship.syslog.proto` | `udp` | `udp` / `tcp` / `tls`（tcp/tls 为长连接，失败自动重建） |
| `logship.syslog.facility` | `4` | facility 0~23；`4` = auth（安全/鉴权消息），常用 `16` = local0 |
| `logship.syslog.hostname` | 空 | 帧内 hostname，空为 `gowaf` |
| `logship.kafka.enabled` | `false` | Kafka 渠道开关（可与 syslog 同时开） |
| `logship.kafka.brokers` | 空 | broker 列表，逗号分隔 |
| `logship.kafka.topic` | 空 | 目标 topic |
| `logship.queue_size` | `4096` | 外发队列容量 |

- Syslog 帧：RFC 5424，STRUCTURED-DATA `SD-ID=gowaf@48577`，携带
  `eventid`、`site`、`ip`、`action`、`ruleid`、`categories`、`method`、`uri`、`ua`、`ja4` 等参数。
- Kafka 消息：完整事件 JSON，key 为客户端 IP（保证同 IP 分区有序）。

## 3. 请求防重放（P1-4）

| 设置键 | 默认 | 说明 |
|---|---|---|
| `guard.replay.enabled` | `false` | 总开关（默认关：只影响显式携带 nonce 的请求） |
| `guard.replay.window` | `300` | 重放判定窗口（秒） |
| `guard.replay.header` | `X-WAF-Nonce` | nonce 请求头名 |

行为：开启后，携带该头且 nonce 非空的请求首次放行并登记；窗口内同 nonce 再次出现直接 403
（响应体 reason=`replay`）。不携带该头的请求不受影响。内存表由 maintenance 协程按窗口自动清理。

## 4. 等候室（P1-5）

上游并发阈值排队（类似 Cloudflare Waiting Room 的单机版）。

| 设置键 | 默认 | 说明 |
|---|---|---|
| `waitroom.enabled` | `false` | 总开关 |
| `waitroom.max_active` | `100` | 同时转发到上游的最大并发数 |
| `waitroom.timeout_ms` | `5000` | 排队等候上限（毫秒），超时返回 429 |
| `waitroom.interval` | `3` | 等候页自动重试间隔（秒） |

- 仅约束真正打到上游的请求；白名单命中、缓存命中、Bot 放行、拦截早退的请求不占用名额。
- FIFO 排队，拿到信号量即放行；排队超时返回 429 + `Retry-After` + meta refresh 等候页。
- 当前活跃数见指标 `waf_waitroom_active`，拒绝数见 `waf_waitroom_rejected_total`。

## 5. 自定义拦截页（P1-6）

站点级配置（`PUT /api/sites/{id}` 传入 `blockPage` 字段，`null` 恢复内置模板）：

```json
{
  "blockPage": {
    "enabled": true,
    "html": "<!DOCTYPE html><html><body><h1>访问被拒绝</h1><p>状态 {{status}}，请求 ID {{reqid}}</p></body></html>"
  }
}
```

- 占位符：`{{status}}`（HTTP 状态码）、`{{reason}}`（拦截原因，HTML 转义）、
  `{{reqid}}`（请求 ID）、`{{site}}`（站点域名）。
- 上限 4096 字节；启用时 HTML 非空，校验失败该站点退回内置模板（fail-open）。

## 6. 控制台 TOTP 两步验证（P1-7）

API-first（Vue 前端未实现，可直接 curl / 自行接入）：

| 端点 | 说明 |
|---|---|
| `GET /api/user/totp` | 查询状态（`enabled`） |
| `POST /api/user/totp/setup` | 生成密钥，返回 `secret` 与 `otpauth://` URL（未启用状态，不落库生效） |
| `POST /api/user/totp/enable` | body `{"code":"123456"}`，验证通过才落库启用 |
| `POST /api/user/totp/disable` | body `{"code":"123456"}`，验证后关闭 |

- 算法 RFC 6238（HMAC-SHA1，30 秒步长，±1 窗口容忍）。
- 启用后登录需额外携带 `totpCode` 字段（`POST /api/auth/login`，body `{"username":...,"password":...,"totpCode":"123456"}`）；
  缺失或错误返回业务码 `40102`（需验证码），并计入登录限流。

## 7. 验证码挑战降级链（P1-8）

环境校验（JS 挑战）失败后的处置序列，替代原先的"纯拒绝"：

| 设置键 | 默认 | 说明 |
|---|---|---|
| `guard.challenge.chain` | `pow` | 逗号分隔子集自 `pow,captcha,ban`。`pow` 纯拒绝（原行为）；`captcha` 降级到图形验证码；`ban` 配合答错超阈值封禁 |
| `guard.captcha.fail_threshold` | `5` | 窗口内答错次数阈值 |
| `guard.captcha.fail_window` | `600` | 失败计数窗口（秒） |

- 推荐 `pow,captcha,ban`：先给图形验证码机会，答错达阈值后封禁 IP。
- 验证码路由：`GET /.waf-captcha/`（出题页，SVG 内嵌 base64 图片，固定 200 返回以便挑战页
  JS fetch 后整体替换文档）、`GET /.waf-captcha/verify?t=<token>&code=<答案>`（提交校验）；
  通过后签发绑定 IP 与过期时间的签名令牌，并 302 回 `to` 参数指定路径（默认 `/`）。
- 换 IP / 篡改 / 过期令牌一律拒绝。服务重启后未通过令牌失效（内存态）。
- 指标：答错 `waf_captcha_fails_total`，通过 `waf_captcha_passed_total`。

## 验收口径对照

| 对比文档条目 | 本实现 | 局限 |
|---|---|---|
| P1-2 JA4 指纹识别 | 事件库记录 JA4 + blocklist 拦截 | 内置恶意清单仅 2 条真实种子，非完整库 |
| P1-3 日志外发 | Syslog RFC5424（udp/tcp/tls）+ Kafka，配置化 | 无重试缓冲持久化（fail-open 丢弃） |
| P1-4 防重放 | 同 nonce 窗口内重放 403 | 单机内存态，多节点不共享 |
| P1-5 等候室 | 并发阈值 FIFO 排队 + 等候页 | 单机版，无跨节点全局配额 |
| P1-6 自定义拦截页 | 站点级模板 + 4 占位符 | 无在线可视化编辑器（API 配置） |
| P1-7 TOTP 2FA | RFC 6238 完整实现 + 登录集成 | 登录页 UI 未加输入框（API 已就绪） |
| P1-8 验证码降级链 | 挑战→验证码→封禁 三级链 | 验证码为算式 SVG，非打码平台对抗级 |
