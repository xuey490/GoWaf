# GoWAF v1.6.1 与雷池（SafeLine）社区版对比

> 对比基线：GoWAF `v1.6.1`（commit 0381720，2026-11-18 正式发布，即分支 feat/p1-v1.7 的「P1 七项」）；雷池社区版 `v9.4.4`（2026-11-11）——**本轮调研确认雷池自 v9.4.4 后未发新版，雷池侧结论与《v1.6.0-与雷池社区版对比》一致，本轮变化全部来自 GoWAF 侧**。
> 雷池数据来源：GitHub Releases（截至 2026-11-18）、README、官方帮助文档。标注「厂商口径」的指标为雷池自行发布，未独立复现。
> 本文只做技术判断，不含商务建议。

---

## 一、结论摘要（相对 v1.6.0 对比的变化）

1. **P1 清单 8 项中 7 项已落地（P1-2~8，全部经代码核实）**：JA4 指纹、Syslog/Kafka 日志外发、防重放、等候室、自定义拦截页、TOTP 2FA、验证码挑战降级链。上一轮「追赶清单」只剩 P1-1（语义广度 + 万级样本库跑分）。
2. **日志外发从「落后」变「反超」**：GoWAF 提供 Syslog RFC5424（udp/tcp/tls）+ Kafka 双渠道、分级过滤、丢弃计数；雷池 CE 文档口径仅 Syslog UDP RFC5424。
3. **自定义拦截页从「双方都缺」变「GoWAF 独有」**：站点级模板 + 4 个占位符（HTML 转义），校验失败回退内置模板；雷池 CE 该能力锁在专业版。
4. **追平项**：防重放（单机内存态，双方一致）、等候室（GoWAF 为单机版 Cloudflare Waiting Room 思路）、TOTP（RFC 6238 自实现，**API 已就绪但控制台 UI 未跟上**）、JA4（算法追平，**内置恶意指纹库仅 2 条种子，清单质量差距明显**）。
5. **剩余差距收敛为四类**：① 语义广度 9 类 vs 宣称 40+ 类 + 大样本跑分（唯一 P1）；② 控制台身份体系（雷池 CE 自 8.6.0 起支持 OIDC，另有 LDAP/CAS/GitHub OAuth 等共 8 种登录方式，GoWAF 仅单管理员 + API Token + TOTP）；③ 人机验证的行为轨迹维度（键鼠轨迹，GoWAF 是环境信号 + PoW）；④ 生态成套度（网关插件发行包、社区规则订阅、文档体量）。
6. **本轮新发现四笔工程债**（诚实口径）：README 宣称的「正则 50ms 超时熔断」实为预留字段未实现；TOTP 无 UI；go.mod 未 tidy（kafka-go 标 indirect 却被直接 import）；仓库根目录混入调试产物（pr*.json / merge*.json / logs_dev.log 等）。

## 二、技术栈与架构

| 维度 | GoWAF v1.6.1 | 雷池 CE v9.4.4 | 评价 |
|---|---|---|---|
| 语言/运行时 | Go 1.27，单静态二进制（`CGO_ENABLED=0`） | 管理面 Go + gRPC；数据面 Tengine(Nginx) + Lua；检测器独立服务（镜像分发） | GoWAF 交付更简单；雷池复用 Nginx 生态 |
| 数据面 | `net/http` + `httputil.ReverseProxy`，HTTP/2，WebSocket 原生升级 | Tengine（Nginx 分支），host 网络 | 雷池的 Nginx 底座在连接管理/TLS 细节更成熟（v9.3.7 起 backlog=65536 + reuseport） |
| 进程模型 | 单进程多核扩展 + 引擎级 panic 隔离 + 超时熔断 | 7 容器（postgres/mgt/detect/tengine/…），进程级隔离 | 雷池故障域更小；GoWAF 运维面为零 |
| 存储 | SQLite（WAL），零外部依赖 | PostgreSQL 15 | 单机 SQLite 足够；多节点必须 PG |
| 前端 | Vue 3.5 + Naive UI + ECharts，`go:embed` 内嵌（224 个 .vue，业务页 17） | 未开源（独立前端包） | — |
| 检测引擎依赖 | Coraza v3.8.1 + OWASP CRS v4.30.0（编译期内嵌）+ libinjection-go v0.3.3 + 自研语义通道 | 自研（闭源二进制分发） | **「读代码学引擎」只有 GoWAF 能做** |
| 指纹/外发新依赖 | JA4 自实现（FoxIO 规范，纯 Go）；kafka-go v0.4.49 | — | JA4 未引第三方库，控制依赖面 |
| 部署形态 | 单二进制 / 宝塔、1Panel、小皮 / 原生 Apache/Nginx/IIS / Windows 服务 / Docker | 仅 Docker Compose，要求宿主机让出 80/443 | **GoWAF 明显占优** |
| 检测接入方式 | `POST /detect` + `GET /check`（auth_request 式），nginx lua / Traefik 示例 | T1K 协议（TCP 8000），ingress-nginx / Kong / Traefik / OpenResty 插件成套 | 能力抹平；**成套度雷池领先** |
| 最低资源 | 单核即可跑 | 1C1G/5GB | 相当 |
| 许可 | AGPL-3.0 | GPL-3.0（个人版许可限制商用） | 定位差异 |
| 开源完整性 | 全栈源码（控制台/规则/脚本） | 管理面开源；**核心检测引擎与 Tengine 镜像二进制分发** | — |
| 社区体量 | 自有仓库（小） | ~24k stars / 1.6k forks | 雷池生态与文档成熟度高一个量级 |

## 三、检测能力

| 能力 | GoWAF v1.6.1 | 雷池 CE v9.4.4 | 说明 |
|---|---|---|---|
| 检测范式 | **四引擎**：自研 YAML 规则（181 条，AC 预筛 + RE2）+ OWASP CRS v4.30（含调度闸门）+ libinjection（SQLi/XSS 词法指纹）+ 语义通道 | 自研语义分析引擎（宣称不依赖规则、防 0day）+ 规则兜底 | **理念差距已消除**；雷池覆盖更广、有样本级验证 |
| 语义覆盖类型 | **9 类**：SQLi、XSS（libinjection）+ cmdi/rce/xxe/ssrf/ssti/expr（JNDI·SpEL·OGNL）/deser | 宣称 40+ 类（SQLi/XSS/代码注入/CRLF/LDAP/XPath/爆破/后门…） | **最大剩余差距**（P1-1）：CRLF/LDAP/XPath/nosqli/穿越/文件包含等 11~13 类缺口已有扩张路线（docs/P1-样本库建设方案.md） |
| 语义判定方式 | 「结构」而非关键词：元字符紧邻系统命令、DOCTYPE+ENTITY 成对、危险 scheme、模板运算链、序列化魔数；单类 35~50 分压在 block 阈值下 | 黑盒，不可考 | GoWAF 语义通道可读可调（例外规则 `sem-*`） |
| 检测前解码 | base64（≤3 层）、gzip/deflate/zlib、JSON/JS `\uXXXX` 多层解码 + 归一化层（URL 多层/HTML 实体/全角/SQL 注释） | 深度解码 + 语义还原 | 相当 |
| **JA4/TLS 指纹** | ✅ **新增**：包装 TLS Listener 偷看 ClientHello（GREASE 忽略），FoxIO 规范自实现，事件库 `events.ja4` 列；`guard.ja4.blocklist` 拦截 + 内置清单开关 | ✅ JA4 + 恶意指纹拦截（8.10.0 起） | **算法与采集追平**；差距在清单质量——GoWAF 内置仅 2 条本机采集种子（`block_builtin` 默认关），雷池为厂商维护清单 |
| 人机验证 | ✅ 三级降级链 **新增**：PoW（16-bit SHA-256 + 浏览器环境信号校验 + 最小耗时）→ 自研算式 SVG 验证码（HMAC 令牌绑 IP，答错 N 次封禁）→ 封禁；`guard.challenge.chain` 可配 | 环境检测（调试行为/**键鼠轨迹**）+ 验证码 | 强度追平；**雷池多「行为轨迹」维度**；GoWAF 无第三方验证码厂商（reCAPTCHA/hCaptcha/Turnstile）——利弊并存（不依赖外网、无隐私外传 vs 无法借力成熟风控） |
| 请求防重放 | ✅ **新增**：nonce 头（默认 `X-WAF-Nonce`）窗口判重 403，窗口/头名可配，内存表自动清理 | ✅ | 追平（双方均为单机内存态） |
| 自定义规则 | 访问策略条件树 + 例外规则 + YAML 热载 | 自定义规则 + 社区在线规则订阅；ASN 匹配锁 Lite/Pro | 雷池有订阅生态；GoWAF 情报源更开放（10 预设 + 自定义 Header/Token） |
| 规则灰度 | Deny 类可先 observe 后 block（引擎模式） | Deny 规则 Monitor 模式（v9.4.4 CE） | 同类能力 |
| 引擎加固 | 超时熔断（`engine.timeout_ms` 默认 2s）+ panic 隔离 + `fail_mode` open/closed；检测 API 独立端口 | 独立检测服务，进程级隔离 | — |
| 威胁情报 | 10 预设源 + 自定义 Header/Token + JSON 列表 | 社区共享情报（内置） | GoWAF 更开放 |
| 效果数据 | 40+ 手工攻击样本（含变形）全检出、benign 零误报；**缺大样本基准** | 33669 样本：检出 71.65% / 误报 0.07%（厂商口径） | P1-1 验收口径：≥10k 样本、检出 ≥70%、误报 ≤0.1% 并公开 |

## 五、性能

### 5.1 本机实测（GoWAF，Windows 6 核 / 回环 / 1.6KB HTML / keep-alive / 无 TLS；v1.6.0 口径，v1.6.1 未重跑）

| 场景 | 吞吐 | p50 | p90 | p99 |
|---|---|---|---|---|
| 裸后端，C=64 | 62,969 RPS | 0.88ms | 1.65ms | 3.29ms |
| 全引擎（v1.5.0 基线，CRS 无治理） | 3,998 RPS | — | — | — |
| **全引擎 + CRS 预筛**，C=64 | **12,836 RPS（3.2 倍）** | 4.4ms | — | 13.5ms |
| 全引擎，C=1（单请求时延） | 916 RPS | **1.04ms** | 1.25ms | 1.86ms |

> v1.6.1 新增组件对热路径的影响均为小常数：JA4 仅在 TLS 握手解析一次 ClientHello（连接级 O(1)，按四元组登记、关闭即清理）；防重放/等候室/日志外发/内置指纹拦截**默认关闭**，开启后均为内存表/信号量/有界队列操作。**但 v1.6.1 尚未重跑基准**，建议发布前补一轮（见工程债）。

### 5.2 与雷池的横向口径

| 指标 | GoWAF v1.6.1 | 雷池 CE v9.4.4 | 说明 |
|---|---|---|---|
| 单请求延迟增量 | ~1.0ms（实测） | <1ms（厂商口径） | 同量级 |
| 单核吞吐 | ~700 RPS（全引擎） | 800 QPS @1C2G（官方） | 同量级 |
| 多核扩展 | ✅ 线性 | ❌ 个人版锁单线程 | **GoWAF 更好** |
| 规模上限 | 无站点数限制 | **10 个站点** | GoWAF 适合多站点托管 |
| 稳定性/隔离 | 引擎级 panic 隔离 + 超时熔断 | 多容器进程级隔离 | 雷池故障域更小 |

## 六、优缺点对照

### GoWAF v1.6.1

| 优势 | 劣势 |
|---|---|
| 单二进制交付，宝塔/1Panel/IIS/Windows 全覆盖，落地摩擦极低 | 语义类型覆盖 9 类 vs 宣称 40+，且缺大样本跑分 |
| 四引擎 + CRS 调度闸门：12.8k RPS、干净流量 100% 旁路 | JA4 内置指纹库仅 2 条种子，拦截主要靠管理员积累 |
| 日志外发双渠道（Syslog tcp/tls + Kafka）+ 告警聚合——CE 无告警外发 | 控制台身份体系单薄：无 SSO/OIDC、无多用户；TOTP 有 API 无 UI |
| 防篡改、脱敏、多上游、地域封禁、自定义拦截页、MCP 可写——CE 多为付费项 | 人机验证无键鼠行为轨迹、无第三方验证码借力 |
| Prometheus 全套打点 + 全栈开源，规则可读可调 | 防重放/等候室/指纹为单机内存态；节点管理半成品 |
| 检测 API 双端点，可作独立引擎被网关调用 | 单进程，故障域大于容器化方案；无压测脚本，性能数据靠手工口径 |

### 雷池 CE v9.4.4

| 优势 | 劣势 |
|---|---|
| 语义引擎宣称 40+ 类，厂商口径检出 71.65%/误报 0.07%（33669 样本） | 个人版裁剪狠：10 站点、单线程 800 QPS、无告警外发、日志不可导出 |
| 产品化成熟：OIDC/LDAP SSO、TOTP、键鼠行为轨迹、等候室、防重放 | 部署重：Docker + PG + 7 容器，必须让出 80/443 |
| 生态：成套网关插件、社区规则订阅、JA4 恶意指纹库、24k stars | 核心引擎闭源，学不到检测算法 |
| v9.4.x 持续加固（面板/引擎边界、容器权限、CVE 响应快） | 多上游/地域封禁/ASN/自定义拦截页锁付费版；自 v9.4.4 未再发版 |

## 七、工程债（本轮代码核实新发现，与雷池无关但影响「完整性」维度）

| # | 事项 | 证据 | 建议 |
|---|---|---|---|

## 九、一句话定位（v1.6.1 版）

> v1.5.0 的判断是「检测理念有代差」，v1.6.0 收窄为「广度差与样本验证」，v1.6.1 之后：**防护面的「付费项对比」基本打完**——防篡改/脱敏/多上游/地域封禁/自定义拦截页/告警外发/日志外发全面反超 CE，防重放/等候室/JA4/TOTP 全部追平。
> 剩下的差距收敛为四件事：**语义广度与样本跑分（P1-1）、控制台身份体系（OIDC+多用户）、JA4 指纹库规模、生态成套度**。
> 现在的格局：**GoWAF = 单机场景下功能最全、落地最快、可读可调的开源 WAF；雷池 = 检测最准、身份与生态最完整的 Docker 型 WAF。** P1-1 做出公开可复现的检出/误报数据 + OIDC 登录补上企业采购门槛，两边的「不可比」就变成了「可选」。
