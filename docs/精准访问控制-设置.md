# 精准访问控制 设置

> 适用版本：v1.3.0 及以上（含「缓存命中不再绕过策略」修复）
> 控制台路径：`#/waf/policies`
> 最后更新：2026-11-16

---

## 一、它解决什么问题

精准访问控制（Access Policy）是 WAF 里**语义最明确、最容易验证**的一层防线：把「谁、从哪里、访问什么、带了什么头」组合起来，命中后按你指定的动作处置。它不依赖攻击特征库，适合处理四类需求：

1. **地域封禁**：拦截荷兰、只放行国内。
2. **单点封禁**：某个 IP 持续扫描，直接封掉。
3. **业务面收敛**：后台接口只允许特定 UA / Cookie / 来源 IP 访问。
4. **灰度观察**：先 `log` 跑一周看命中量，确认无业务流量后再切 `block`。

它与「规则检测」是并行关系：规则看内容像不像攻击，策略看来源和对象该不该来。两者互不替代。

---

## 二、四个核心概念

| 概念 | 说明 |
|---|---|
| **条件树** | 一条策略 = 一棵条件树。同层条件按「且 / 或」组合，深层可嵌套分组，最深 4 层、单策略最多 64 个条件。 |
| **处置动作** | 命中后做什么：放行 / 拦截 / 人机校验 / 封禁 / 仅记录。 |
| **优先级** | 数字**小的先命中**，同优先级按创建 ID 升序。**第一条命中的策略即最终结论**，后续策略不再评估。 |
| **生效站点** | 留空 = 全站生效；填写时必须是**站点名称**（如 `goframe.phpframe.org`），不是域名列表里的别名。 |

热生效：保存即写入数据库并触发运行时热加载，**不需要重启服务**（已实测）。

## 三、请求处理顺序（决定策略何时生效）

数据面按固定顺序处理每个请求，策略排在第 8 步：

| 序号 | 阶段 | 说明 |
|---|---|---|
| 1–3 | 路由 / IP 白名单 / 封禁检查 | 已封禁 IP 在此被拒，走不到策略 |
| 4 | **Bot 检测** | UA 明显是扫描器（如 `osint-scanner`）会在此拦掉 |
| 5 | 静态资源与白名单路径标记 | 仅打标记，**不跳过策略** |
| 5.6 | 人机校验（可疑导航 / 超频） | 下发挑战页 |
| 6 | 限流 | 超频返回 429 |
| **6.4** | **策略提前判定（本次新增）** | 只处理「不依赖 body + 拒绝类动作」的策略 |
| 6.5 | 页面缓存查找 | 命中直接返回 |
| 7 | 读取请求体 | 有站点级上限 |
| **8** | **策略完整求值** | 含 body 条件、allow、log |
| 9–10 | 规则检测 / 转发回源 | — |

由此得到三条必须记住的结论：

1. **策略救不回已被 Bot 拦掉的请求。** 想放行某类扫描器 UA，要在 Bot 管理或 IP 白名单里处理，策略写「放行」无效——它在第 8 步，Bot 在第 4 步。
2. **6.4 与第 8 步的语义完全一致。** 6.4 只对「第一条命中的策略」下手，且该策略必须不依赖 body、动作是 `block/ban/challenge`。若第一条命中依赖 body，或是 `allow/log`，一律交回第 8 步，绝不改结论。
3. **缓存命中不再绕过策略。** 修复前已缓存的 js/css 对境外 IP 仍返回 200（实测复现），现已由 6.4 兜住。

## 四、可用的条件字段

| 字段 | 引擎取到的值 | 示例 | 备注 |
|---|---|---|---|
| `client_ip` | 真实客户端 IP | `96.126.130.106` | 已按可信代理链还原 XFF |
| `country` | **归一化后的归属地整串** | `荷兰`、`中国 广东 深圳`、`中国香港` | 海外只到国家；国内到省市 |
| `region` | 恒为空串 | — | **配置后永不命中**，别用 |
| `host` | 请求 Host | `goframe.phpframe.org` | 含端口时原样保留 |
| `method` | HTTP 方法 | `POST` | 大写 |
| `path` | URL 路径（已解码、不含参数） | `/api/login` | 匹配用这个，不要带 `?` |
| `query` | 原始查询串 | `id=1&from=bd` | 整串比较 |
| `ua` | User-Agent | `Mozilla/5.0 …` | 可 `exists false` 抓空 UA |
| `referer` | Referer | `https://a.com/` | 同上 |
| `content_type` | Content-Type | `multipart/form-data` | 常用 `prefix` |
| `body` | 请求体文本 | `union select` | **依赖它就无法在缓存前判定** |
| `header.X` | 任意请求头 | `header.X-Forwarded-For` | 大小写不敏感，多值逗号合并 |
| `cookie.X` | 指定 Cookie 值 | `cookie.session` | 按名字精确取 |
| `arg.X` | query 参数或表单字段 | `arg.token` | 同名时 query 优先 |
| `query.X` | 仅 query 参数 | `query.page` | 重复参数取第一个 |

> `country` 的取值直接来自内置 IP 库的归一化结果，海外是**中文国家名**，因此必须写「荷兰」而不是 `Netherlands` / `NL`。

## 五、可用的操作符

| 操作符 | 界面文案 | 语义 | 必须注意 |
|---|---|---|---|
| `eq` | 等于 | 全等 | 区分大小写，除非勾「忽略大小写」 |
| `ne` | 不等于 | 全等取反 | **字段不存在时左边是空串，会命中**，容易误伤 |
| `contains` | 包含 | 子串 | 同上 |
| `prefix` | 前缀 | 以…开头 | 匹配省市、路径前缀最常用 |
| `suffix` | 后缀 | 以…结尾 | 单值字面量，不支持 `a,b` 列表 |
| `regex` | 正则 | Go `MatchString`，**子串匹配** | 必须自己写 `^…$`，否则 `/x.js.bak` 也命中 |
| `cidr` | CIDR | 网段包含 | 支持 `1.2.3.0/24`，**也支持裸 IP**（自动按 /32） |
| `in` | 属于列表 | 逗号分隔，逐项全等 | 英文逗号，不能有空格以外的分隔 |
| `gt/ge/lt/le` | 大于/大于等于/小于/小于等于 | 数值比较 | 只对能解析成数字的值有效，如 `header.Content-Length` |
| `exists` | 存在 | 只判断有没有，不看内容 | 值只能填 `true` / `false` |

## 六、五种处置动作

| 动作 | 行为 | 适用场景 |
|---|---|---|
| **放行** `allow` | 跳过后续全部 WAF 检测，直接回源 | 内网、合作方回调、搜索引擎 |
| **拦截** `block` | 返回 403 拦截页，事件落库 | 地域封禁、单 IP 封禁、后台收敛 |
| **人机校验** `challenge` | 下发校验页，通过后 30 分钟内免校验（绑定 IP） | 疑似爬虫但不敢直接拒 |
| **封禁** `ban` | 返回 403 并把来源 IP 写入封禁表 | 明确恶意来源，需要连带拦截整机 |
| **仅记录** `log` | 不拦截，只写事件并继续检测 | 灰度观察，上线前必做 |

## 七、页面填写指引

新增/编辑策略时，表单字段与含义一一对应：

| 表单项 | 填什么 | 建议 |
|---|---|---|
| 规则名称 | 能一眼看懂的名字 | 建议「动作-对象」，如 `拦截-荷兰` |
| 生效站点 | 留空或站点名 | 留空 = 全部站点 |
| 处理动作 | 五选一 | 先 `log` 再 `block` |
| 优先级 | 1–9999，越小越先 | 放行类 1–10，精确封禁 20–50，地域封禁 100，兜底 1000 |
| 启用 | 开关 | 保存后即时生效 |
| 备注 | 变更原因 | 建议写「谁、为什么、何时可撤」 |
| 条件逻辑 | 且 / 或 | 可视化模式下同层统一逻辑 |
| 高级开关 | 打开后改为编辑 JSON | 需要嵌套分组时必须打开 |

**可视化模式**：字段 + 操作符 + 值，逐行添加；右侧小开关是「忽略大小写」。

**高级模式**：直接编辑条件树 JSON，支持任意嵌套。

```json
{
  "logic": "and",
  "items": [
    { "field": "country", "op": "eq", "value": "荷兰" },
    { "field": "path", "op": "prefix", "value": "/admin" }
  ],
  "groups": [
    {
      "logic": "or",
      "items": [
        { "field": "method", "op": "eq", "value": "POST" },
        { "field": "method", "op": "eq", "value": "PUT" }
      ]
    }
  ]
}
```

上面这条的语义是：`荷兰` **且** `路径以 /admin 开头` **且**（`POST` **或** `PUT`）。

## 八、典型配置模板

以下配置均已在生产库验证过语法，可直接照抄后改值。

| 目标 | 逻辑 | 条件（字段 / 操作符 / 值） | 动作 | 优先级 |
|---|---|---|---|---|
| 拦截荷兰全境 | 且 | `country` / 包含 / `荷兰` | 拦截 | 100 |
| 拦截指定 IP | 且 | `client_ip` / 等于 / `96.126.130.106` | 拦截 | 20 |
| 拦截一个 C 段 | 且 | `client_ip` / CIDR / `96.126.130.0/24` | 拦截 | 20 |
| 只封某省 | 且 | `country` / 前缀 / `中国 广东` | 拦截 | 100 |
| 只保护单站点 | 且 | `host` / 等于 / `goframe.phpframe.org` | 拦截 | 100 |
| 封 WordPress 探测 | 且 | `country` / 等于 / `荷兰` ＋ `path` / 包含 / `wp-login` | 拦截 | 50 |
| 封已知扫描器 UA | 且 | `ua` / 包含 / `osint-scanner` | 封禁 | 10 |
| 封空 UA 脚本 | 且 | `ua` / 存在 / `false` | 拦截 | 30 |
| 后台接口只允许 POST | 且 | `path` / 前缀 / `/api/admin` ＋ `method` / 不等于 / `GET` | 拦截 | 50 |
| 拦跨站直接提交表单 | 且 | `method` / 等于 / `POST` ＋ `referer` / 存在 / `false` | 拦截 | 80 |
| 未登录禁止进后台 | 且 | `cookie.session` / 存在 / `false` ＋ `path` / 前缀 / `/admin` | 拦截 | 50 |
| 放行内网 | 且 | `client_ip` / CIDR / `10.0.0.0/8` | 放行 | 1 |
| 灰度观察境外流量 | 或 | `country` / 等于 / `美国` ＋ `country` / 等于 / `德国` | 仅记录 | 500 |

**编排顺序建议**：放行（1–10）→ 精确封禁（20–50）→ 业务约束（50–80）→ 地域封禁（100）→ 兜底记录（500–1000）。

## 九、上线与验证

**第一步：先 `log` 跑一天。** 到「事件」页按策略名筛选，确认命中的确实是该拦的流量。

**第二步：切 `block` 后用 curl 验证。**

```bash
# 应返回 403，且响应头带 X-WAF-Reason: policy
curl -sI https://goframe.phpframe.org/ -H 'User-Agent: Mozilla/5.0'

# 看是否被拦、被谁拦
curl -s -o /dev/null -D - https://goframe.phpframe.org/some/path | grep -i x-waf
```

**两种 403 要分清**（判断到底是谁拦的）：

| 页面标题 | 含义 | 判断依据 |
|---|---|---|
| `403 请求被拦截` | 策略 / 规则 / 封禁 | 响应头 `X-WAF-Action: block`、`X-WAF-Reason: policy` |
| `安全校验` | 人机校验挑战页 | 不是拒绝，通过后即放行 |

**第三步：看命中量。** 列表里的「命中次数」由后台任务**每 60 秒**批量刷库，刚配完看到的 0 是正常的，最多延迟一分钟。若长期为 0，按下一节排查。

## 十、已知限制

| 限制 | 影响 | 规避方式 |
|---|---|---|
| `region` 字段恒为空 | 用它写的条件永不命中 | 用 `country` 前缀匹配省市 |
| 依赖 `body` 的条件无法在缓存命中路径生效（6.4 会跳过） | 命中缓存的静态资源不受 body 类策略约束 | 静态资源不要用 body 条件；要拦资源用 `path`/`country`/`ip` |
| Bot 检测在策略之前 | 策略的 `allow` 救不回被 Bot 拦掉的请求 | 在 Bot 管理 / IP 白名单里放行 |
| `ne` 与 `exists` 对缺失字段的处理 | 字段不存在时可能命中 | 组合策略时优先用 `eq`/`prefix` 正向条件 |
| 单策略 64 条件、条件树最深 4 层 | 超出会在保存时报错并拒绝 | 拆成多条策略，用优先级控制顺序 |
| 条件为空会被拒绝保存 | 「空条件匹配所有请求」太危险 | 至少给一个具体条件 |
| 命中计数延迟 60 秒 | 列表数字滞后 | 看「事件」页可实时确认 |

## 十一、排障对照表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 保存成功但一直不命中 | 全局开关 / 条件写错 / 被更靠前的策略抢先 | 查优先级、查 `region` 是否被误用、临时把优先级调到 1 |
| 命中次数一直是 0 | 流量在第 4 步被 Bot 拦掉，没走到第 8 步 | 看事件表该 IP 的 UA，改在 Bot 管理里配 |
| 想放行的请求仍被拦 | 策略晚于 Bot / 限流 | 用 IP 白名单或 Bot 白名单 |
| 静态资源没被拦住 | 修复前的缓存旁路 | 升级到含 6.4 的版本 |
| 地域条件完全不生效 | 写成了 `Netherlands` / `NL` | 改成中文国家名 |
| 正则命中一堆不该拦的 | 用了子串匹配 | 补 `^…$` |
