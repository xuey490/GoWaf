# 页面密码 / 访问认证（auth 动作）设置指南

> 适用版本：v1.5.0+ · 所属模块：精准访问控制 · 控制台入口：**访问策略**

## 一、这是什么

给指定页面或路径加一道「进门密码」：

- **page 模式**：访客首次访问时看到密码页，输入密码后拿到通行证 Cookie（默认 8 小时有效、绑定 IP），期间不再重复询问。适合保护内部文档、临时演示页、后台入口。
- **basic 模式**：标准 HTTP Basic 认证，浏览器弹原生用户名/密码对话框；API 客户端（curl、程序）天然支持，适合保护 API 与运维端点。

对应雷池（SafeLine）的「认证挑战」能力。

## 二、工作原理

```
请求 → 精准访问控制(早期阶段,缓存之前) → 命中 auth 策略
  → 已持有通行证 Cookie / Basic 凭据正确？──是──→ 放行（继续限流/检测/转发）
  └──否→ page: 密码页(403) ──POST /.waf-auth/<策略ID>──→ bcrypt 校验 → 签发通行证 → 跳回原页
          basic: 401 + WWW-Authenticate（浏览器弹框）
```

关键设计：

1. **门禁在缓存之前执行**：命中缓存的静态资源同样要过认证，不存在"已缓存页面绕过密码"；
2. **密码只存 bcrypt 哈希**：明文只在控制台创建/修改时经过内存，落库的是哈希，接口回显一律 `******`；
3. **通行证按策略独立**：Cookie 名为 `waf_auth_<策略ID>`，绑定客户端 IP + 过期时间，HMAC 签名防伪造；多个认证策略各自持票互不影响；
4. **完整求值免疫**：auth 策略只在早期阶段执行一次，不会因为后续检测再次弹窗。

## 三、控制台配置步骤

1. 进入 **访问策略 → 新增策略**；
2. 填写策略名称、生效站点（留空 = 所有站点）、优先级；
3. **动作**选择「访问认证(auth)」；
4. 配置条件：例如保护后台入口 → 字段 `path`、操作符 `prefix`、值 `/admin`；保护整个内部文档区 → `path` 前缀 `/docs`；
5. 认证配置区块：
   - 模式选 `page`（密码页）或 `basic`（HTTP 认证）；
   - page：填访问密码（编辑时留空 = 不修改）、可改标题、通行证时长（小时，默认 8）；
   - basic：添加账号（用户名 + 密码），可多账号；Realm 留空用默认 `Restricted`；
6. 保存即可生效（无需重启）。

### 典型场景

| 场景 | 条件配置 | 认证配置 |
|---|---|---|
| 保护后台入口 | path prefix `/admin` | page，密码页标题「管理后台」 |
| 内部文档区 | path prefix `/docs` | page，通行证 24 小时 |
| 保护 API | path prefix `/api/private` | basic，账号 devops |
| 临时演示页 | host eq `demo.example.com` | page，通行证 2 小时 |

## 四、API 配置示例

创建 page 模式策略（保护 /admin）：

```bash
curl -X POST http://127.0.0.1:8899/api/policies \
  -H "Authorization: <access token>" -H "Content-Type: application/json" \
  -d '{
    "name": "后台入口密码",
    "site": "",
    "priority": 50,
    "enabled": 1,
    "action": "auth",
    "conditions": "{\"logic\":\"and\",\"items\":[{\"field\":\"path\",\"op\":\"prefix\",\"value\":\"/admin\"}]}",
    "config": {"mode": "page", "title": "管理后台", "password": "your-password", "ttlHours": 8}
  }'
```

创建 basic 模式策略（保护 /api/private）：

```bash
curl -X POST http://127.0.0.1:8899/api/policies \
  -H "Authorization: <access token>" -H "Content-Type: application/json" \
  -d '{
    "name": "API 认证",
    "action": "auth",
    "conditions": "{\"logic\":\"and\",\"items\":[{\"field\":\"path\",\"op\":\"prefix\",\"value\":\"/api/private\"}]}",
    "config": {"mode": "basic", "users": [{"user": "devops", "password": "your-password"}]}
  }'
```

修改时**密码留空（或不传 password 字段）= 沿用原密码**；basic 模式按用户名沿用旧哈希。

## 五、配置项说明

| 字段 | 说明 | 取值 |
|---|---|---|
| `mode` | 认证方式 | `page` 密码页 / `basic` HTTP Basic |
| `password` | page 模式访问密码（明文仅提交时使用） | 任意非空；落库为 bcrypt |
| `users` | basic 模式账号列表 | `[{user, password}]`，至少 1 个 |
| `title` | 密码页标题 | 留空用「访问验证」 |
| `realm` | Basic 认证 realm | 留空用 `Restricted` |
| `ttlHours` | page 通行证有效期（小时） | 默认 8，上限 720 |

## 六、注意事项

1. **条件不能依赖 body**：auth 是缓存之前的门禁动作，条件树引用 body 字段会被编译拒绝（这是有意设计，否则已缓存资源绕过门禁）；
2. **换 IP 需重新认证**：通行证绑定客户端 IP，移动网络下 IP 漂移会重新弹一次密码，属预期行为；
3. **退出登录**：清除浏览器的 `waf_auth_<策略ID>` Cookie 即可；
4. **密码页本身会被门禁放行**：`/.waf-auth/<策略ID>` 是解锁通道，先于所有闸门处理，不会被限流/挑战挡住；
5. **多策略叠加**：同一请求命中多条 auth 策略时按优先级取第一条——优先级更高的门禁通过后，低优先级策略不再重复询问；
6. **观察模式不弹窗**：引擎处于 observe 模式时 auth 门禁不生效（观察模式 = 只记录不拦截）。

## 七、常见问题

**Q：能和 IP 白名单共存吗？**
能。IP 白名单优先级最高（第 1 步），白名单 IP 直接放行，不触发认证。

**Q：curl 怎么访问受保护的 API？**
basic 模式：`curl -u devops:password https://site/api/private/...`；page 模式：先 `curl -c jar -d "password=xxx" https://site/.waf-auth/<策略ID>?to=/目标路径` 拿 Cookie，再 `-b jar` 访问。

**Q：忘记密码怎么办？**
在访问策略里编辑该策略、填写新密码保存即可，无需重启。
