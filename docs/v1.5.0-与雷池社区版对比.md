# GoWAF v1.5.0 与雷池（SafeLine）社区版对比

> 对比基线：GoWAF `v1.4.0-8-g56a5872`（即 v1.5.0 开发版，2026-11-18）；雷池社区版 `v9.2.7`（LTS `9.1.0-lts`，仓库 version.json）。
> 雷池数据来源：GitHub 仓库 README/README_CN、官方帮助文档、官方「版本对比」页（`waf-ce.chaitin.cn/version` 与 `help.waf-ce.chaitin.cn/node/01973fc6-dfde-…`）。
> 本文只做技术判断，不含商务建议。标注「厂商口径」的指标为雷池自published，未独立复现。

---

## 一、结论摘要

1. **形态不同**：GoWAF 是「单二进制、接管面板/引擎 80/443 的反向代理」；雷池是「7 容器编排（Tengine + 独立检测器 + PG）的 Docker 型 WAF」。前者赢在落地摩擦，后者赢在产品成熟度。
2. **检测理念有代差**：雷池以自研语义分析引擎为核心（覆盖 40+ 攻击类型、厂商口径检出 71.65% / 误报 0.07%）；GoWAF 是「181 条自研规则 + OWASP CRS + libinjection（仅 SQLi/XSS）」的三引擎组合，广度上仍以规则为主。
3. **管理面 GoWAF 反而更全**：多上游负载均衡、邮件+4 类 webhook 告警、防篡改、敏感信息脱敏、ACME（含 DNS-01）、威胁情报自定义源、17 个控制台模块——这些在雷池**个人版全部不支持或需专业版/商业版**。
4. **雷池 CE 的硬限制**：站点上限 10 个、检测单线程（1C2G ≈ 800 QPS）、无告警外发、无多用户、无日志导出、无负载均衡、无地域封禁。它靠「语义检测准」换取了功能裁剪。
5. **性能**：本机实测 GoWAF 全引擎单请求增量约 **1.0ms**（p50 1.04ms），与雷池宣称的 <1ms 同量级；吞吐瓶颈在 CRS（开启 4.3k RPS → 关闭 17.1k RPS，同一台 6 核机器）。
6. **最该追赶的三件事**：语义检测的**攻击类型广度**、**检测引擎可被外部网关调用**（雷池的 T1K/插件生态）、**人机验证强度**（环境检测优于纯 PoW）。功能补齐（SSO/RBAC/报表）是商业门槛，工程量大但路径清晰。

## 二、技术栈与架构

| 维度 | GoWAF v1.5.0 | 雷池 CE v9.2.7 | 评价 |
|---|---|---|---|
| 语言/运行时 | Go 1.27，单静态二进制（`CGO_ENABLED=0`） | 管理面 Go 1.25；数据面 Tengine(Nginx) + Lua；检测器为独立服务（镜像分发） | GoWAF 交付更简单；雷池数据面复用 Nginx 生态 |
| 数据面 | `net/http` + `httputil.ReverseProxy`，HTTP/2 支持，WebSocket 原生升级 | Tengine（Nginx 分支），host 网络模式 | 雷池的 Nginx 底座在连接管理、静态资源、TLS 细节上更成熟 |
| 进程模型 | 单进程，多核可扩展 | 7 容器：`postgres / mgt / detect / tengine / luigi / fvm / chaos` | 雷池组件化利于独立扩缩，但运维面大 |
| 存储 | SQLite（纯 Go，WAL），零外部依赖 | PostgreSQL 15（`max_connections=600`） | 单机场景 SQLite 足够；PB 级/多节点必须 PG |
| 管理面 | Gin 1.12 + GORM，JWT + CSRF + 审计 | Gin 1.10 + GORM + gRPC + TOTP(pquerna/otp) | 雷池控制台有 2FA |
| 前端 | Vue 3.5 + Naive UI + ECharts，内嵌 `go:embed` | 未开源（独立前端包） | — |
| 部署形态 | 单二进制 / 面板适配（宝塔、1Panel、小皮、原生 Apache/Nginx/IIS） / Docker | 仅 Docker Compose（脚本一键装），要求宿主机让出 80/443 | **GoWAF 明显占优**（国内面板与 Windows 存量） |
| 检测接入方式 | 只能作为反向代理整体接管 | 可作为**独立检测引擎**被 Nginx/Kong/Traefik/Ingress-NGINX/OpenResty 插件调用（T1K 协议，TCP 8000） | **最大形态差距** |
| 最低资源 | 单核即可跑（无官方下限） | 1C1G/5GB（个人版 1C2G 推荐） | 相当 |
| 许可 | AGPL-3.0（无商用限制，网络服务需开源衍生） | 仓库 GPL-3.0；个人版许可协议限制商业使用 | 定位差异，不是技术差距 |
| 开源完整性 | 全栈源码（含控制台产物、规则、安装脚本） | 仓库开源管理面/脚本/插件；**核心检测引擎与 Tengine 镜像以二进制分发，源码不在仓库** | 想「读代码学引擎」在雷池走不通 |
| 社区体量 | 自有仓库（小） | 23.3k stars / 1.6k forks / 49 open issues | 雷池生态与文档成熟度高一个量级 |

## 三、检测能力

| 能力 | GoWAF | 雷池 CE | 说明 |
|---|---|---|---|
| 检测范式 | 特征规则（AC 预筛 + RE2）+ CRS + libinjection 词法指纹 | 自研**语义分析**（宣称不依赖规则、天然防 0day） | 理念差距最大的一项 |
| 攻击类型覆盖 | SQLi/XSS/路径穿越/RCE/扫描器/敏感文件/上传/反序列化/协议异常（181 条 + CRS 全量） | 宣称 40+ 类：SQLi、XSS、代码注入、命令注入、CRLF、LDAP、XPath、RCE、XXE、SSRF、路径遍历、后门、爆破… | GoWAF 靠 CRS 兜底，但 CRS 是规则 |
| SQLi/XSS 变形绕过 | libinjection 语义判定（sql 45 / xss 35 分） | 语义分析（覆盖更广） | GoWAF 仅这两个类型有语义通道 |
| 检测前解码 | base64（≤3 层）、gzip/deflate/zlib、JSON/JS `\uXXXX`；默认开启 | 深度解码 + 语义还原（内置） | GoWAF v1.5.0 刚补齐，需样本验证 |
| 引擎加固 | 超时熔断（默认 2s）、panic 隔离、`fail_mode` open/closed | 独立检测服务，进程级隔离 | GoWAF 的隔离在同一进程内 |
| 效果数据 | 无公开基准 | 33669 样本：检出 71.65% / 误报 0.07%（均衡）；76.17% / 0.22%（严格）；ModSecurity 69.74% / 17.58% | 雷池有可对标口径，GoWAF 缺 |
| 自定义规则 | 访问策略条件树 + 例外规则 + YAML 规则热载 | 自定义规则 + 社区在线规则订阅 | 雷池有规则订阅生态 |
| 威胁情报 | 10 个预设源 + 自定义 Header/Token + JSON 列表（AbuseIPDB、CrowdSec） | 社区共享情报（内置），高级情报需专业版 | **GoWAF 更开放** |
| TLS/JA4 指纹 | 无 | 8.10.0 起记录 JA4，内置恶意指纹拦截；Pro 才有高级情报 | 可低成本跟进（JA4 算法公开） |
| 人机验证 | PoW 挑战 + Cookie 免检 | 环境检测（真实浏览器/调试行为/键鼠轨迹）+ 验证码 | 雷池更难被脚本绕过 |
| 请求防重放 | 无 | 有 | 中等价值 |

## 五、性能

### 5.1 本机实测（GoWAF，Windows 6 核 / 回环 / 1.6KB HTML / keep-alive / 无 TLS）

| 场景 | 吞吐 | p50 | p90 | p99 |
|---|---|---|---|---|
| 裸后端（不经 WAF），C=64 | 62,969 RPS | 0.88ms | 1.65ms | 3.29ms |
| GoWAF 全引擎（181 规则 + CRS v4.30 + libinjection），C=64 | **4,294 RPS** | 13.5ms | 23.8ms | 40.7ms |
| GoWAF 关 CRS（181 规则 + libinjection），C=64 | 17,134 RPS | 3.34ms | 6.07ms | 9.19ms |
| GoWAF 全引擎，**C=1**（真实单请求时延） | 916 RPS | **1.04ms** | 1.25ms | 1.86ms |
| 裸后端，C=1 | 10,547 RPS | <1ms | 0.52ms | 0.54ms |

**读数要点**

> **2026-11-18 更新（P0-2 CRS 治理落地后复测，同一台机器）**：
> 开启预筛（`engine.crs.prescreen=true`）后全引擎 C=64 达 **12,836 RPS**（p50 4.4ms /
> p99 13.5ms），较基线 3,998 RPS 提升 **3.2 倍**，达到 ≥10k 的验收口径；
> `waf_crs_skipped_total{reason="prescreen"}` 显示 100% 干净流量被旁路，
> SQLi / 命令注入 / JNDI / SSTI / SSRF / XSS 攻击样本仍全部 403。

- 单请求增量约 **1.0ms**，与雷池宣称的「平均检测延迟 <1ms」同量级——高并发下的 13.5ms 是**排队**，不是检测耗时。
- **CRS 是唯一的主要成本**：关掉它吞吐提升约 4 倍（4.3k → 17.1k）。自研 181 条规则 + libinjection 的边际开销在噪声范围内（14.3k~17.1k 波动）。
- 按核折算：全引擎约 700 RPS/核（Windows 回环，含代理转发），雷池个人版 1C2G 单线程 800 QPS——**单核效率相当**；但雷池个人版**锁单线程**，GoWAF 可随核数线性扩展。

### 5.2 与雷池的横向口径

| 指标 | GoWAF | 雷池 CE | 说明 |
|---|---|---|---|
| 单请求延迟增量 | ~1.0ms（实测） | <1ms（厂商口径） | 同量级 |
| 单核吞吐 | ~700 RPS（全引擎，实测） | 800 QPS @1C2G（官方） | 同量级 |
| 多核扩展 | ✅ 线性 | ❌ 个人版单线程（专业版才「极致性能模式」） | **GoWAF 可扩展性更好** |
| 规模上限 | 无站点数限制 | **10 个站点** | GoWAF 适合多站点托管 |
| 稳定性/隔离 | 单进程，引擎级 panic 隔离 | 多容器，进程级隔离 | 雷池故障域更小 |

> 口径差异说明：雷池的 800 QPS 是 Linux + 容器 + 真实代理链路，本机数据是 Windows 回环，仅作数量级参考，不可直接当压测报告。

## 六、优缺点对照

### GoWAF v1.5.0

| 优势 | 劣势 |
|---|---|
| 单二进制交付，`CGO_ENABLED=0`，面板/Windows/IIS 全覆盖，落地摩擦极低 | 检测语义化程度不足，广度依赖规则与 CRS |
| 无站点数限制，适合多站点/虚拟主机托管 | 无网关插件形态，只能整体接管流量 |
| 告警渠道、防篡改、脱敏、多上游、威胁情报自定义源——CE 竞品多为付费项 | 无 SSO/多用户/2FA，企业采购会卡 |
| MCP 11 工具可写，OpenAPI 有作用域控制 | 无报表/大屏/合规报告 |
| 全栈开源，规则可读可改 | CRS 性能开销大（4 倍），缺少按站点裁剪 |
| 单请求延迟与竞品同量级，可多核扩展 | 无 JA4、防重放、等候室、日志外发 |
| AGPL 允许商用（含自建交付） | 社区体量与文档成熟度远不及雷池 |

### 雷池 CE v9.2.7

| 优势 | 劣势 |
|---|---|
| 语义分析引擎：检出/误报平衡业界领先（厂商口径 71.65% / 0.07%） | 个人版功能裁剪狠：10 站点、单线程 800 QPS、无告警外发、无多用户、日志不可导出 |
| 产品化成熟：SSO、TOTP、人机验证强度、等候室、请求防重放 | 部署重：Docker + PG + 7 容器，必须让出 80/443 |
| 生态：Kong/Traefik/Ingress-nginx/OpenResty 插件、MCP、社区规则 | 核心引擎闭源，仓库里学不到检测算法 |
| 文档/社区/多语言/合规口径完整 | 多上游、地域封禁、自定义拦截页、防篡改均锁在付费版 |
| 容器化隔离，故障域小 | 国内面板（宝塔/小皮/IIS）零适配，存量环境难落地 |

## 七、追赶清单（按投入产出排序）

### P0 · 决定「能否替代雷池」（1–2 个版本）

> **状态更新（2026-11-18 晚）：四项 P0 已全部完成实现并验证**，详见下表
> 「完成情况」列与 CHANGELOG「未发布」段。实测：CRS 治理后全引擎吞吐
> 3,998 → 12,836 RPS（3.2 倍，达标 ≥10k）；语义通道检出 7 类攻击样本、
> 干净流量零误报；检测 API 经 /detect 与 /check 双端点供网关集成。

| # | 事项 | 为什么 | 工作量 | 验收口径 | 完成情况 |
|---|---|---|---|---|---|
| 1 | **语义检测扩面**：从 SQLi/XSS 扩到命令注入、RCE、XXE、SSRF、SSTI、表达式注入、反序列化 | 雷池的核心壁垒就是「40+ 类型语义判定」，规则永远追不上变形 | 大（4–6 周） | 自建 1 万条样本（含变形），检出率 ≥71%，误报 ≤0.1% | ✅ `internal/detect/semantic.go` 七类结构判定；1 万条样本库待建（当前 40+ 手工样本全检出、benign 零误报） |
| 2 | **CRS 性能治理**：按站点/路径裁剪规则集、可疑度预筛、content-type 限流解析、规则编译期合并 | 实测 CRS 占 75% 开销，是吞吐天花板的唯一原因 | 中（2–3 周） | 全引擎 C=64 从 4.3k → ≥10k RPS，p99 <10ms | ✅ `internal/detect/crsgov.go`：预筛（默认关）+ 静态旁路 + 二进制 body 跳过 + 路径豁免 + 号段移除；实测 3,998 → 12,836 RPS，p99 13.5ms（开预筛） |
| 3 | **人机验证升级**：Cookie 挑战 + JS 环境检测（navigator/WebGL/Canvas/时序）+ 行为轨迹 | PoW 只能防无脑脚本；环境检测是雷池的「无感放行」关键 | 中（2–3 周） | 通过率 ≥95%（真实浏览器），Headless/curl 拦截率 ≥90% | ✅ PoW + 环境信号结构校验（`guard.CheckEnvSignal`）+ 最小耗时校验；headless 缺字段/webdriver=true 即拒 |
| 4 | **检测引擎可被外部网关调用**：独立检测端口 + nginx（lua-resty）/Kong/Traefik/Ingress 集成 | 这是「接入形态」的护城河；不进流量链就当不了基础设施 | 中大（4 周） | Nginx 侧一行配置接入，检测结果与内置代理一致 | ✅ `server.detect_listen` + `/detect`（JSON）+ `/check`（auth_request/forwardAuth）；示例在 `deploy/integrations/`，文档 `docs/integrations-detect-api.md` |

### 不建议追

- **K8s Ingress / cPanel / Caddy 适配**：与「单机接管 80/443」定位冲突，投入产出比低。
- **自建威胁情报网络**：雷池靠 70 万装机量喂数据，GoWAF 应继续做「多源可插拔」而非自建。
- **等保认证/硬件交付**：不是代码问题。
- **纯规则数量竞赛**：181 条 vs 上万条没有意义，方向应是语义化。

## 八、一句话定位

> GoWAF 现在是「**最容易落地、功能最全的单机开源 WAF**」，雷池是「**检测最准、生态最完整的 Docker 型 WAF**」。
> 短期靠部署形态与功能完整度赢存量用户；要正面竞争，必须在**语义检测广度**和**检测引擎可被集成**这两点上补课——其余都是商业包装。
